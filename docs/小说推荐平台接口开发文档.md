# 墨读·小说引力场 — 接口需求文档

> 文档状态：2026-08-06 按「游客可浏览、登录才可写」改版全量修订；2026-08-07 增量更新（后端落地状态：意见反馈/系统通知/后台公告与反馈管理接口、后端接口文档双 spec）。
> 本次修订要点：① 明确公开读接口与需登录写接口的分级（书评列表、话题列表、书籍/话题详情页均免登录）；② 移除已删除的 `BookDetailModal` / `PostDetailModal` 契约，改为独立详情页；③ 补充此前未提及的契约：路由表、token 鉴权协议、游客模式规则、话题乐观更新、SEO/sitemap、后端新增删除评论接口等。
>
> 项目为**前端 SPA + 后端 novel 模块**架构：前端（`src/`）通过 `fetch` 调用后端 REST 接口（`/web-api/v1/app/novel/**`，Gin + GORM，见 `docs/novel模块修复记录.md`）。本文档中的"接口"指以下三类契约：
> ① 前端 → 后端 REST 接口（`src/api/`，含鉴权分级与请求协议）
> ② 数据模型接口（前端 `src/types.ts` 与后端 DTO 的映射，`src/api/mappers.ts`）
> ③ 组件 Props 接口与业务操作接口（路由页面、AppContext 事件契约）

## 2. 接口访问规则（本版核心变更）

> 原则：**列表与详情读接口一律免登录**；`mine=1` / `isCollected=1` 等"我的"维度与全部写接口需登录。

### 2.1 公开接口（免登录，游客可访问）

| 接口 | 说明 | 前端用途 |
|---|---|---|
| `GET /app/novel/home` | 首页聚合（精选 + 热门 + 话题） | 游客首页数据、游客书籍/话题兜底 |
| `GET /app/novel/book` | 书库列表（分页/筛选/排序） | 书库页、游客书籍列表 |
| `GET /app/novel/book/:id` | 书籍详情（点击当日去重） | BookDetailPage |
| `GET /app/novel/book/rank?type=rating\|click` | 榜单 | ⚠️ 后端已实现，前端 RankPage **未调用**（改用 `GET /book` 全量数据客户端排序，见 §4.1） |
| `GET /app/novel/book-review/page` | 书评列表（分页；`mine=1` 需登录） | 书评圈 ReviewsPage（仅传 `filter='all'`，`high_rating/hot` 为 CommunityReviewsView **客户端筛选**）；书籍详情书评 Tab 数据来自书籍详情的 `reviews[]`，不走此接口 |
| `GET /app/novel/post/page` | 话题列表（分页） | 长文广场 PostsPage、首页长文区 |
| `GET /app/novel/post/:id` | 话题详情 | PostDetailPage |
| `POST /app/novel/user/login` | 登录（失败统一 41033，防枚举） | AuthModal |
| `POST /app/novel/user/register` | 注册（自动建档案并签发 token） | AuthModal |

### 2.2 需登录接口（Bearer token，未登录返回 401/业务码）

| 接口组 | 接口 | 说明 |
|---|---|---|
| 书籍写 | `POST /book`、`PUT /book/:id`、`DELETE /book` | 发布/编辑/删除作品 |
| 书评写 | `POST /book-review`、`DELETE /book-review` | 提交书评（事务聚合评分）、删除书评 |
| 话题写 | `POST /post`、`DELETE /post` | 发布/删除长文 |
| 话题互动 | `POST /post/:id/interact`（`type=like/dislike/collect`，`action=add/cancel`） | 点赞/点踩/收藏（互斥事务） |
| 评论写 | `POST /post/:id/comment`（`content/replyToUser/parentId`）、`DELETE /post-comment/:id` | 发表/回复评论、删除评论 |
| 我的数据 | `GET /post-comment/mine`、`GET /post/page?mine=1`、`GET /book-review/page?mine=1`、`GET /post/page?isCollected=1` | 我的评论/话题/书评/收藏的话题 |
| 书架 | `GET /bookshelf`、`POST /bookshelf`、`DELETE /bookshelf/:id` | 书架列表/加入/移除 |
| 关注 | `POST /follow`、`DELETE /follow/:targetUserId`、`GET /following`、`GET /profile/:userId` | 关注/取关（幂等）、我的关注、书友名片聚合 |
| 资料 | `GET /reader-profile`、`PUT /reader-profile` | 我的资料 |
| 意见反馈 | `POST /feedback`（body `{type: A~H, content, kind?}`，kind=feedback/complaint） | ✅ 后端已实现（2026-08-07）；提交成功自动生成系统通知；`GET /feedback/page?kind=` 查询我的反馈/投诉 |
| 系统通知 | `GET /notification/page`、`GET /notification/unread-count`、`POST /notification/read`（body `{ids?}`，空=全部已读） | ✅ 后端已实现（2026-08-07）；读者端通知收件箱（来源：系统/公告/反馈回复） |

### 2.3 前端游客模式规则（AppContext）

- 首屏加载仅调 `homeApi.home()`（公开）；**游客**书籍列表 = `home.featured + home.hotBooks` 去重（`dedupeBooks`），话题列表 = `home.latestPosts`。
- **登录后**（或已有 token 刷新页面）：并行拉取 `reader-profile`、`book-review/page?mine=1`、`post/page?mine=1`、书架、关注列表。
- 所有写操作入口在未登录态**不发写请求**，采用两级守卫：
  - **页面级守卫**（组件内 `!isLoggedIn → setAuthOpen(true)` 弹 AuthModal）：HomePage（发布长文）、PostCard（赞/踩/收藏/评论/回复/关注）、PostDetailPage（同 PostCard + 作者关注）、BookDetailPage（发表书评/加入书架/编辑作品）、BookCard / LibraryBookRowCard / HeroCarousel（书架收藏）、UserDetailModal（关注）。
  - **Context 级兜底守卫**（`!getToken() → toast('请先登录后再…') + return`，凭据缺失即中断、不发请求）：`toggleBookshelf` / `addReview` / `saveBook` / `publishPost` / `likePost|dislikePost|collectPost` / `addPostComment` / `toggleFollowUser`。
  - **PostsPage 例外**：列表内点赞/点踩/收藏不做登录弹窗，采用**本地乐观更新 + 接口失败回滚**（未登录请求返回 401，`.catch` 回滚并 toast「操作失败，请重试」）；仅发帖（弹 AuthModal）与评论/回复（走 `addPostComment` Context 守卫）有守卫。
- 游客评论表单替换为「登录后 才能发表研讨回复、点赞与关注书友」CTA 引导条。
- 已登录接口失败（401/网络异常）静默降级，不阻塞浏览；`logout` 清空 token 与全部用户态数据。

## 3. 数据模型接口

前端模型定义于 `src/types.ts`（`Book/Review/Post/PostComment/UserProfile/FollowedUser/CarouselSlide` 等），由 `src/api/mappers.ts` 将后端 DTO（`src/api/types.ts`）映射而来。核心字段如下（与后端字段的映射差异以 mappers.ts 为准）：

**Book**（映射自 `NovelBookDTO`）：`id, title, author, cover, rating, reviewCount, status(serialStatus), category, tags, slogan, description, clicks, publishDate, wordCount(万字→数字, 展示层格式化), chapters, reviews[], isFeatured, url(readUrl)`。

**Review**（映射自 `NovelBookReviewDTO`）：`id, bookId, bookTitle, bookCover(book 关联), userName, avatar, rating(1~5), content, likes, date(createdAt)`。

**Post**（映射自 `NovelPostDTO`）：`id, title, userName, avatar, content, summary, date, wordCount, readTime, likes/isLiked, dislikes/isDisliked, collections/isCollected, comments[], tags[], bookTitle/bookId`。

**PostComment**（映射自 `NovelPostCommentDTO`）：`id, postId, userName, avatar, parentId, replyToUser, content, likes, date(createdAt), replies[](楼中楼)`。

**UserProfile / FollowedUser**：`name/avatar/bio/email/joinDate/preferredCategories`；关注项 `{id, name, avatar, bio, isFollowed}`。

**SystemNotification**（`src/types.ts`）：`{id, title, content, time, read}` —— 系统通知。✅ 后端已实现（`app_novel_notification`，2026-08-07），前端仍以 `localStorage['modu_notifications']` 占位，接入后切换为 `GET /notification/page` + 未读数 + 标记已读接口。

**FeedbackRecord**：`{type(A~H 字母), typeLabel, content, createdAt(ISO), kind?: 'feedback'|'complaint'}` —— 反馈/投诉记录。✅ 后端已实现（`app_novel_feedback`，2026-08-07），前端仍以 `localStorage['modu_feedback']` 占位，接入后切换为 `GET /feedback/page?kind=`。

> 说明：`date: '刚刚'/'10分钟前'` 等相对时间为前端展示层格式化；后端下发 ISO 时间戳（`createdAt`）。

## 5. 业务操作接口（AppContext 事件契约）

> 所有写操作先做登录守卫（§2.3），再调对应 `src/api/novel.ts` 接口；成功后更新本地 state 并 toast，失败 toast 错误信息。

### 5.1 鉴权

| 操作 | 实现 | 说明 |
|---|---|---|
| `login(username, password)` | `authApi.login` → `setToken(token)` → 拉取用户数据 | 成功 toast「欢迎回来」 |
| `register(username, password)` | `authApi.register` → 同上 | 注册即登录 |
| `logout()` | 清 token + 全部用户态 | toast「已退出登录」 |
| `isLoggedIn` | `!!getToken()` | 每次渲染实时判定 |

### 5.2 数据加载

| 操作 | 说明 |
|---|---|
| 首屏 `homeApi.home()` | 游客/登录用户通用；游客用 featured+hotBooks 兜底书籍、latestPosts 兜底话题 |
| `refreshUserData()` | 登录后：profile + 我的书评 + 我的话题 + 书架 + 关注（并行） |
| `refreshBooks()` / `refreshPosts()` | 登录后全量书籍 / 首页话题（话题接口公开） |

### 5.3 写操作（均需登录）

| 操作 | 接口 | 规则 |
|---|---|---|
| `toggleBookshelf(bookId)` | `POST/DELETE /bookshelf` | 有则移除（按书架记录 id），无则加入；刷新书架 |
| `addReview(bookId, review)` | `POST /book-review` | 评分 1~5；刷新书详情（`openBookById` 重新拉取） |
| `saveBook(book)` / `deleteBook` | `POST|PUT /book`、`DELETE /book` | 新增/编辑/删除作品 |
| `publishPost(post)` | `POST /post` | 发布长文 |
| `likePost/dislikePost/collectPost(postId)` | `POST /post/:id/interact` | 赞/踩互斥；PostsPage 另做本地乐观更新 + 失败回滚（`applyPostUpdate` 同步 selectedPost/列表） |
| `addPostComment(postId, content, replyToUser?)` | `POST /post/:id/comment` | 返回 `Promise<boolean>`；成功后 `applyPostUpdate` 本地追加评论 |
| `deletePost(postId)` / `deleteComment(commentId)` | `DELETE /post`、`DELETE /post-comment/:id` | 仅作者/本人可删 |
| `toggleFollowUser(userName, avatar?, bio?)` | `POST /follow`、`DELETE /follow/:targetUserId` | 不能关注自己；幂等；刷新关注列表 |
| `openUser({name, avatar, bio})` | `GET /profile/:userId` | 打开书友名片（弹 UserDetailModal） |

### 5.4 详情页联动（URL 驱动）

`openBook/openPost` → 置 `selectedBook/selectedPost` → Layout effect 导航到 `/book/:id|/post/:id`；离开该路由 → `closeBook/closePost`。直达 URL 时由 Route 内 `openBookById/openPostById` 拉取完整数据并更新列表（`openPostById` 从 `[...posts, ...userPosts, ...(selectedPost?[selectedPost]:[])]` 先查本地，未命中才请求）。

### 5.5 意见反馈 / 投诉（新增，前端占位实现）

| 操作 | 入参 | 规则 |
|---|---|---|
| `openFeedback(draft?)` | `draft?: { typeIndex?: number\|null; content?: string; kind?: 'feedback'\|'complaint' }` | AppContext 暴露：无 draft 为普通反馈（类型空选）；带 draft 则 FeedbackModal 预选类型 + 预填内容；`kind` 标记反馈/投诉归属（投诉按钮一律传 `'complaint'`） |
| `submitFeedback` | `type: A~H, content: string(≤500字), kind` | ① 未登录（`!isLoggedIn`）→ toast「请先登录后再提交反馈」+ 弹 AuthModal，不发请求；② 未选类型/内容为空 → 表单内联错误提示；③ 成功 → toast「反馈已提交，感谢你的宝贵建议！」+ 关闭并清空表单，同时向 `modu_notifications` 追加一条「反馈/投诉已提交」系统通知 |
